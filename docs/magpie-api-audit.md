# Magpie 集成：哪些已经跑通

更新：2026-11-18。[返回文档目录](README.md)

本机 Windows amd64 的真实 Magpie 独立副本已经运行插件工厂、MCP 工具、中间件和官方 service-page iframe。没有修改用户日常 Magpie 配置；上游全部为本机合成夹具，不包含真实模型采样。

| 能力 | 已观察结果 |
| --- | --- |
| 页面入口 | 真实宿主服务 iframe 内完成目标增改、Enter 提交、手动检测、原始回答、预算和备份恢复 |
| 参考库页面 | 导入原始 bundle、显示重算的六分区指标和原始来源记录；合成库不出现真实来源审核/激活资格 |
| MCP 工具 | `targets/check/report/cancel` 按宿主命名注册，执行受本机预算控制的独立检测 |
| 渠道认证 | 非流式与 SSE 的 route V3 签章通过；上游伪造公开字段无效 |
| 路由组 | 实际有序组第一次供应商失败、第二供应商成功，记录最终供应商和 attempt_count=2 |
| 普通请求 | 启用、停用、请求错误和额度耗尽后仍正常通过 |
| 生命周期 | 取消或关闭插件停止在途请求，关闭本机监听；重新启用后保留目标、原始回答、历史与额度 |
| 数据 | schema v1 SQLite、WAL 一致只读旧库迁移、幂等迁移、恢复与不退额度机制有自动测试 |
| 密钥 | stdin 私有配置、Windows 保护 DACL、私有运行目录；不进入页面配置、报告、导出及上游 |

## 当前宿主缺少什么

`onProvider` 是请求观察钩子，并非最终网络传输证明。Magpie 后续仍可能转换/整理包体，其他插件也可能介入。插件顺序及 metadata 只能说明观察拓扑，不能证明最终送出的请求与参考实验完全相同。

因此当前插件运行时始终令 `protocol_guard=false`，实际样本 `protocol_verified=false`。route V3 的请求摘要与完整响应签章不取代这项证明。Go 内部适配器有未来可信宿主接入的测试分支，但当前插件不打开它。

界面已在 Magpie 0.1.3960 的独立副本验证。发布工具另固定校验下载 Magpie CLI v0.1.4361 和 Windows Bun 1.4.4；安装验收与页面验收分别记录，不能笼统称为所有版本或平台都通过。更换宿主/架构后重新跑原生安装门槛。

精确源码和早期调查保留在[接口核查原文](technical/magpie-api-audit.md)，最后发布成绩看[当前进度](p0-report.md)。

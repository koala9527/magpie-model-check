更新：2026-11-18。[返回文档目录](README.md)

## 仍然存在的限制

| 问题 | 当前处理 | 后续要求 |
| --- | --- | --- |
| 真实模型参考样本为 0 | legacy 描述性、synthetic 只检验机制，概率 null | 明确预算和 Policy 后独立采样，保存真实来源证据 |
| 宿主缺少最终上游请求证明 | protocol_guard 固定 false，不输出经过身份准入的结论 | Magpie 提供最终请求证明后再独立接入与验证 |
| 来源真实性不能从 hash 得到 | 本机逐条审核和 HMAC 只绑定审核事实，不自动认证现实标签 | 审核人提供独立可复查来源，公开数据局限 |
| 观察跨渠道/日期的外推有限 | 只接受独立验证覆盖的具体渠道/UTC 日期组合 | 新渠道和日期须新数据，不能自动沿用旧结论 |
| 跨平台运行证据不齐 | 六目标编译和原生安装任务分开计数 | 对应 CI 原生安装任务成功后才宣传平台实测 |
| 文件路径 TOCTOU | 拒绝 symlink、hardlink、重解析点，收紧权限；发布互斥覆盖整个事务 | 同一用户恶意改路径不属于内核级隔离保证 |
| 异常终止留下 publication lock | fail-closed 报错，不按锁年龄偷删别的发布者 | 确认无实例运行后处理锁，见故障排查 |
| 协议规范化差异 | 非规范响应可能保守地拒绝认证 | 若扩展响应格式，增加独立规范化对照；不放宽为部分字段签章 |

## 本轮关闭的主要软件风险

- 旧门禁和日志触发不再拦截/消耗普通请求。
- 实际官方服务页面支持增改、Enter、检测、历史、预算和参考资料操作。
- 停用/取消停止在途请求；超时和失败持久化，带退避；重启不重放付费请求。
- 全局并发、请求和 Token 预算持久保存；恢复/删历史不退额度。
- route V3 绑定完整响应，SSE 链包含前序事件；重试超时不沿用旧供应商。
- 备份不会导入可信身份或渠道权威；参考标记/指标一律重算。
- Windows DACL、私有目录、子进程环境、已知密钥反射的 metadata/raw 脱敏具有回归测试。
- 同一轮所有样本验证 UTC 日期及实际 provider/model，跨日或渠道变化拒绝判断。
- 运行时密钥发布在跨进程独占锁内读取前值、原子发布、终检和回滚。

## 运行时启动问题

`ROUTE_PUBLICATION_BUSY` 表示另一个发布事务或异常遗留锁占用了私有运行目录。正常并发启动不会自动覆盖密钥，失败回滚不会改掉较新的成功发布。先停止该插件的所有实例，确认 `plugin/.runtime/route-publication.lock` 没有活跃所有者，再备份该目录并处理遗留锁；不要在运行中反复删除。

Windows 日志轮转的旧失败与早期缺 CGO 的日志保留为基线；后续测试用独立记录说明，不改写历史失败。最终结果看[当前进度](p0-report.md)，原问题编号见[技术问题记录](technical/risk-register.md)。

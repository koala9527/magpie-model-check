## 2. 建立第一版真实参考实验

开始付费采集前，把以下内容写清楚：

- 哪些真实模型、版本和家族进入已知名单；哪些模型留作未知测试。
- 要适用哪些渠道和 UTC 日期；相邻版本、渠道变化和上游更新时间怎样覆盖。
- 提示词、系统提示词、解析器与请求参数的完整协议；不同协议分别做实验，不混在同一份结果里。
- 请求、Token 和费用上限，以及超时、失败、超预算的停止条件。
- 谁逐条审核来源，怎样核验模型标签、渠道、日期、请求和原始回答。
- 明确的 Policy：置信水平、误认/误报上限、未知识别和正确识别目标、允许拒绝判断比例。程序没有自动通过的默认门槛。

[参考库指南](reference-library.md)包含数据模板、分组规则和实际准入流程，可直接复用。

## 3. 保持实验数据相互独立

| 数据用途 | 用来做什么 | 不能拿来做什么 |
| --- | --- | --- |
| 建库 `reference` | 建立每个已知模型的参考中心 | 当作最终测试成绩 |
| 校准 `calibration` | 推导经验判断包络；含专门的未知校准模型 | 再把同一批模型或近似回答当最终未知测试 |
| 已知测试 `test` | 检查已知模型及相邻版本表现 | 回写阈值 |
| 未知测试 `unknown_test` | 检查库外模型的识别与误认 | 从已知名单里强行挑身份 |
| 留渠道 `channel_holdout` | 检查建库/校准未见过的渠道，覆盖已知与未知样本 | 与其他分区复用渠道 |
| 留时间 `time_holdout` | 在其他分区之后的 UTC 日期检查变化，覆盖已知与未知样本 | 用未来测试数据修补原阈值后沿用旧测试成绩 |

组、采集批次、会话和请求必须按真实采集事实区分。当前检查要求 UTC 日期不跨分区；同批的多轮测试不拆成多个“独立组”，也不靠改 ID 增加样本量。Wilson 区间按独立完整组计数，程序的分组检查本身不证明现实中的独立性。

## 4. 什么时候可以启用真实参考库

按顺序完成：

1. 保存原始回答及来源证据，核对协议和 raw hash，生成原始 bundle。
2. 导入后检查原始数据、分组和指标，而不是读取文件自带的“已验证”标记。
3. 本机审核人逐条核验所有记录，绑定当前 bundle、corpus 和 provenance hash，填写全部 Policy 字段。
4. 服务重新计算参考中心、校准规则和独立测试指标；查看不足项及每个版本/渠道的结果。
5. 只有真实来源、独立指标和协议兼容全部通过，才显式激活。当前 Magpie 宿主缺少最终上游请求证明，运行时因此保守保持 `protocol_verified=false`；需宿主能力改进后，才有可能输出身份结论。

审核通过与身份验证是两回事。当前真实参考样本仍为 0，合成实验和内置 legacy 资料保持描述性，概率保持 `null`。

## 5. 一轮实验不通过时怎样推进

保留这轮结果，说明缺少的分区、样本、来源核验或未达目标的统计区间。优先补真实独立数据或缩小声明的适用范围，不降低目标来“改绿”。如果改变算法、题目、参数、模型名单或校准方法，就登记新版本，并准备新的最终测试；不把已经看过的 holdout 重新称为未见数据。

恢复备份或修改参考文件/Policy 后，重新审核、重评并显式激活。恢复尝试的本机审核作废规则见[参考库指南](reference-library.md#恢复与导出)。
